<span class="topic-title">Codex“永久缓存”是持久化KV缓存，不是内存常驻</span>
</summary>

<div class="topic-content" markdown="1">

<div class="topic-article" markdown="1">

### 核心内容
Tibo 称 Codex 对登录用户“永久保留缓存”，并保证回到旧会话时命中缓存。主帖质疑：缓存是昂贵内存，怎么可能长期保留？评论区的共识是，这里的“永久”指**持久化缓存**（落盘），而非把 KV cache 常驻显存或内存。

### 关键要点
- 传统 API 的 KV cache 多为内存缓存，有效期通常只有 5~10 分钟，工具调用稍久就会过期，下一轮按全价计费。
- 落盘缓存可把有效期拉长到数小时；OpenAI Developers 帖称 API 可选 `12h` 档，或与默认 30 分钟档混用，写入计费约为普通输入的 2.5 倍。
- “缓存永久保留”不等于“永久缓存”：需要反复在同一会话对话来刷新过期时间，或借助 Agent 的“缓存保温”定时发消息。
- 有回复估算 KV cache 体积：4bit 量化下 256k 上下文约 180MB，用户量乘以多会话、subagent、换模型各存一份，成本并不小。

### 评论补充
有观点认为所谓“永久”可能只是计费层面的模拟：过期未命中时免掉相应费用，用户感知不到差别。也有人猜测是本地加密后上传远端解密，但被反驳磁盘与传输成本不现实。DeepSeek 此前曾宣传用磁盘做缓存以降低 token 成本，可作参照。

<div class="topic-content" markdown="1">

<div class="topic-article" markdown="1">

### 核心内容
作者用 DeepSeek 辅助逆向小米运动（手机计步，非手环）的卡路里算法，发现其核心逻辑与运动生理学关系不大，且存在重复累加 bug。

### 关键要点
- **步频分档计卡**：每分钟步数 ≤138 按 0.04 卡/步；139–277 按 0.06 卡/步；≥278 按 0.10 卡/步。最后一档约 4.6 步/秒，人类几乎无法整分钟维持，实际只用前两档。
- **距离取整丢精度**：距离 = 步数 × 0.6，但每次同步都先 `int(n × 0.6)` 再累加，n=13 时 7.8 变 7，同步越勤丢得越多，显示值约 0.59 而非 0.6。
- **卡路里重复累加（bug）**：同一分钟内每次更新不是覆盖最新值，而是把旧值再累加一遍。对照实验：正常走 54 步得 2.16 卡（正确）；边走边下拉刷新走 40 步得 8.28 卡，折合 0.207 卡/步，超过其最高档一倍。
- **复现方法**：`adb logcat -G 128M && adb logcat -c`，走 5 分钟后 `adb logcat -d -v brief ＞ walk.log`，搜 `srcDataMap = {calories=[...]`，看同一 `time=` 的 calories 是否递增。注意 logcat 分段每行带 `I/fitness_xxx(pid):` 前缀，需先剥前缀再处理换行。

### 评论补充
有回复指出一直以为卡路里与心率联动，结果主要靠步数；也有人称早期睡眠检测同样不靠谱，并类比小米电饭煲各功能功率相同、仅换名称。这些属个人经验，未提供数据验证。

结论：首屏卡路里数字可偏 30%~100%，偏差还取决于是否频繁刷新，参考价值有限。

<span class="topic-title">sing-box 1.14.3 升级后 Bus error 与 DNS 解析失败的修复步骤</span>
</summary>

<div class="topic-content" markdown="1">

<div class="topic-article" markdown="1">

### 核心内容

作者将多台 VPS 的 sing-box 升级到 1.14.3 后，节点全部失效，其中一台出现 `Bus error`。排查发现是磁盘写满导致二进制损坏，修复后又遇到 DNS 解析失败，最终 Shadowsocks 与 VLESS REALITY 均恢复，无需重装系统或重配节点证书。

### 关键要点

- **先看服务状态**：`systemctl status sing-box --no-pager -l` 显示 `status=7/BUS`，执行 `sing-box version` 也报 Bus error，说明应优先怀疑二进制本身，而非节点配置。
- **查磁盘**：`df -h /` 显示 2GB 磁盘 100% 占用；`du -ah /var/log | sort -hr | head -30` 定位到 `access.log` 达 772MB。用 `truncate -s 0` 清空，避免 `rm -rf /var/log/*` 误删。
- **重装二进制**：备份原文件后，从官方 GitHub Release 下载 1.14.3 的 linux-amd64 包，先运行 `version` 验证，再用 `install -m 755` 替换 `/etc/sing-box/bin/sing-box`。作者注明磁盘满导致损坏只是推测，未做校验和验证。
- **修 DNS**：日志出现 `org.freedesktop.resolve1 was not provided by any .service files`，原配置为 `"dns": {}`。改为 `local` 服务器并设 `"prefer_go": true`、`"final": "local"`，绕开不可用的 systemd-resolved D-Bus 路径；改完用 `sing-box check` 校验再重启。
- **防复发**：日志级别从 `info` 降到 `warn`，并配置 logrotate（`size 10M`、`rotate 3`、`compress`、`copytruncate`）。

### 评论补充

有回复认为 sing-box 配置协议变动频繁、升级排错成本高，主张“能用就别升级”；作者也认同，并提到 AI 对排错帮助很大。

＞ 注意：以上路径与配置仅适用于 systemd 且安装在 `/etc/sing-box/bin/sing-box` 的环境，其他安装方式需调整；已有复杂 DNS 规则时不要整体覆盖。

### 关键要点
- **专业术语是知识压缩协议**：开发者说“失焦”，背后包含定义、触发时机、状态影响、边界规则与行业惯例；外行只能描述“点到别处输入框就不对了”，问题难以被准确分析。

结论：AI 时代的专业能力在于识别问题、找到合适概念、补全隐藏规则并验证结果；不知道该问什么，答案就很难对准真正的问题。

### 评论补充
